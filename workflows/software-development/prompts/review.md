# Software Development Workflow — Technical Review

Review the actual Git diff against the approved plan and acceptance criteria.

## Requirements

- This is a read-only review: do not edit or write files.
- Do not commit, push, or create a pull request.
- Check correctness, regressions, error handling, edge cases, security, performance, tests, compatibility, and documentation when relevant.
- Report only actionable technical findings with severity, path, impact, evidence, and recommended fix.
- End with `WORKFLOW_STATUS: REVIEW_NO_FINDINGS` or `WORKFLOW_STATUS: REVIEW_FINDINGS`.
